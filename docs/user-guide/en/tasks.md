A task combines a title, description, workflow state and people responsible for the work. Its key remains useful in chat links, activity and integrations.

## Create a task {#create-a-task}
Use New task, quick add, or the add control within a task group. In a folder-scoped view, verify the proposed folder. Write a short action-oriented title, then add acceptance criteria in the description.

Opening a task displays its full detail view. Edit its title and description directly where offered; commit the edit using the displayed save control. Closing an unsaved editor can discard its draft.

## Update attributes {#update-attributes}
- Status describes progress. Project workflow settings can add states and choose their colors.
- Priority describes urgency and is separate from status.
- Assignees supports several people. Open the people selector, check members, then Apply; Cancel leaves the previous assignment unchanged.
- Due date is the planned deadline, not the last-modified timestamp.
- Labels provide additional classification; folders provide a navigable hierarchy.

Editable table cells let you update these values without repeatedly opening the task. Your account must have write access.

## Configure workflow states {#configure-workflow-states}
An administrator can open Configure statuses next to the task’s status controls.
Set a state’s display name and color, then save that row. To add a state, enter its
name, choose a color and submit the creation form. The project’s menus and boards
use these definitions. A custom state name is user-authored and is not translated
automatically when someone changes interface language.

## Track work {#track-work}
Use checklists for small verification steps, subtasks for independently tracked work, and comments for discussion. Attach images or videos by dropping files into the task. Open Relations to manage dependencies and Activity to inspect changes.

If another member edits the same item, a conflict can require a reload before retrying. Keep your draft separately if necessary; do not blindly overwrite a newer revision.

Completing a parent does not automatically execute its subtasks. See [hierarchy and dependencies](doc:hierarchy) and [files and media](doc:files-media).
